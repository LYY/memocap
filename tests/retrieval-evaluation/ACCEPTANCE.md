# Frozen Synthetic Evaluation Contract (v1)

Frozen before the first holdout execution. All names, paths and destinations are invented. Corpus membership, IDs, expectations and these rules must not change to make a retrieval experiment pass. A future corpus revision is a separate benchmark, with a new freeze digest and a newly measured baseline.

The 12 tuning queries and 12 holdout queries have disjoint family names and different mechanisms. Repeated wording controls exist only within tuning (Chinese exact/paraphrase, Deployment early/late, service local/cross-origin). Holdout expected data lives separately in `holdout.expected.json`. The public holdout is a regression holdout, not a blind statistical sample. No ranking/model parameters are selected in this baseline. Subsequent experiments select all parameters on tuning, record/freeze the chosen configuration and numerical resource ceilings before opening holdout, and run holdout once for that decision. Changing parameters after reading holdout requires a new independent holdout.

The fixed comparison budget is top 3 and 6000 CLI content characters plus the actual plugin reference block's 6000 UTF-16 character limit. Baseline uses the imported current plugin `queryTerms`, `any` and current selected-repository scope (attached domain and universal included). A cross-origin positive is deliberately a failure under current scope. The fixture is not authorization to broaden a production host's permissions. All synthetic A/B origins are explicitly created and owned by this evaluator. Future library-authority options must be the actual parent-approved CLI options and must appear in the recorded argv. An explicit universal selector must remain effective.

For positives, hit@1 and hit@3 and reciprocal rank use the first expected ID in the returned list; MRR is zero on a miss. Most cases require every expected ID; `idRule:any` permits either duplicate as the answer. ID coverage is the expected-ID fraction found; duplicate cases count as one answer unit. Concept coverage is a conservative fixture annotation check: a concept counts only when an expected record carrying it was injected with its full original content. This is not an LLM judgment of semantic correctness. Case success requires the ID rule, all expected concepts preserved and no forbidden ID returned. A hit can therefore coexist with an integrity or applicability failure. Candidate coverage uses receipt `matched_ids` if available; in 0.5.0 these are visible pre-budget matches, after scope and topic shadowing, not every raw lexical candidate or every record in the DB.

No-answer success requires an empty returned list. Negative noise is the fraction of no-answer cases with any result; also report their total returned items. Wrong-environment noise is the fraction of `environmentCheck` cases returning a forbidden ID. This measures exposure of an inapplicable reference, not whether an agent executed it. Topic conflicts are separately checked for the expected independent fact and forbidden same-topic reference. Invalidated routes are relevant answers only with their invalidation/verification context intact, never permission to execute. Explicit-origin leakage means any returned ID outside the selector.

Report each case, split, family and expected origin; aggregate positives separately from negatives (never average negatives into hit/MRR). p50/p95 use nearest-rank quantiles of one sequential end-to-end CLI invocation per query, including process startup and activity receipt work, excluding seed/resolve and reference rendering. One sample per case is descriptive, not a stable performance benchmark. Record DB file bytes after seed and after evaluation; it includes data, indexes and activity, so standalone index footprint and RSS are unavailable. Record reference block characters and complete/partial IDs. Do not count a truncated reference as a full answer merely because its ID ranked well.

Adoption calculation, fixed before holdout: compare paired case success/failure counts, hit/MRR, negative and environment exposures and resource measurements under the same budget; list every newly fixed and newly broken case. Safety gates are zero forbidden-environment exposure, explicit-selector leakage, or partial content presented as complete. Recall alone cannot prove execution safety. Preserve exact-anchor successes. A quality winner must fix at least one missed positive without regressing any previously successful positive or increasing negative noise; otherwise report a tradeoff and require an explicit product decision. There is no fabricated universal percentage improvement or latency threshold. Resource ceilings must be chosen from corrected lexical/tuning measurements and the actual device before a model experiment; until then resource acceptance is undecided. More noise cannot be hidden by a higher mean hit rate or by increasing the budget.

Capture cases are separately labeled evidence/admission expectations from the approved improvement plan (which intentionally supersedes the existing docs-exist exclusion). They are not fed into retrieval or silently seeded as extra records. No capture admission precision, coverage, readback, duplicate-rate or real-user capture claims are produced until an implemented capture worker is actually driven. Missing workflows are capture examples, not historical-memory recall failures. The seeded routing memories here are synthetic assumed-existing memories.
